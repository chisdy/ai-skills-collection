# 平台差异

HIG「Getting started → Designing for …」各页的浓缩。同一个功能在不同平台上应该长得不一样，原因是**显示、人机工程、输入方式、使用时长**四个维度都不同。做多平台移植时，逐平台对照本文件。

## 1. 四维度对照表

| 平台 | 显示 | 人机工程 | 输入 | 交互时长 |
|---|---|---|---|---|
| iOS | 中等高分屏 | 单/双手握持，距离 30–60cm，横竖切换 | 多点触控、虚拟键盘、语音、传感器 | 1–2 分钟到 1 小时+，频繁切换 app |
| iPadOS | 大屏，可外接 | 手持或放置，触控 + 键盘 + 指针 + Apple Pencil | 触控、键盘、触控板、Pencil | 中长时长，多窗口并行 |
| macOS | 大高分屏，可多显示器 | 坐姿，距离 30–90cm | 键盘、指针、游戏手柄、Siri | 几分钟到数小时深度工作，多 app 并行 |
| watchOS | 极小屏，Always On | 手腕上，距离 <30cm，另一只手操作 | 触控、Digital Crown、语音、手势 | <1 分钟的瞥视，一天多次 |
| tvOS | 大屏 HD/4K | 距离约 3m，沙发 | 遥控器焦点导航、Siri、游戏手柄 | 沉浸式媒体，较长 |
| visionOS | 无边界空间 | 佩戴，视觉舒适度优先 | 眼睛注视 + 手指捏合，直接触碰，语音 | 可长可短，需持续关注舒适度 |

## 2. iOS

最佳实践：

- **限制屏幕上的控件数量**，让人专注于主要任务；次要细节与操作用最少的交互可发现（滑动、长按、菜单）。
- 无缝适配 **横竖屏、深色模式、Dynamic Type**。
- 顺应握持方式：**屏幕中下部更容易触达**，让列表行支持滑动操作，支持滑动返回。
- 在获得许可后利用平台能力（支付、生物识别、位置）减少用户输入。

系统特性：Widgets、主屏幕快捷操作、Spotlight、快捷指令、活动视图（分享）。

导航：Tab Bar（顶层，通常 ≤5 项）、Navigation Stack（层级）、模态 Sheet（独立任务）。iOS 27 起 iPhone app 可以选择用 Sidebar 呈现 Tab（`sidebar.preferredPlacement = .sidebar`），但这是 app 的决定，UI 上不能切换。导航栏可随滚动收起（`barMinimizationBehavior`）。

## 3. iPadOS

- 窗口可**任意缩放到最小尺寸**，行为接近 macOS。**先为全屏设计**，尽量晚地切到紧凑布局；变窄时先隐藏第三栏（Inspector），再收 Sidebar。
- 测试半屏、三分之一、四分之一等系统常用窗口尺寸，转换要平滑。
- **可转换 Tab Bar**：`tabViewStyle(.sidebarAdaptable)` 让 Tab Bar 与 Sidebar 互相切换；Tab Bar 展示顶层区域，Sidebar 展示更丰富的层级（`TabSection`）。启动时选一种，用户可切换、可自定义（拖放排序、收藏）。
- 支持键盘快捷键、指针悬停效果、拖放（含从 Files 拖入拖出）、多窗口（Scenes）、Apple Pencil（如相关）。
- iPad 用户期待 app 能无缝移到外接显示器并任意缩放。

## 4. macOS

最佳实践：

- **利用大屏**：更少的嵌套层级、更少的模态，展示更多内容，但保持舒适的信息密度。
- **窗口自由**：可缩放、隐藏、显示、移动；支持全屏模式。
- **菜单栏承载全部命令**，包括工具栏与右键菜单里有的。
- **高精度输入**：像素级选择与编辑。
- **键盘快捷键**：支持纯键盘工作流；不要覆盖系统快捷键。
- **个性化**：可自定义 Toolbar、窗口配置、颜色与字体。

系统特性：菜单栏、文件管理（Open/Save 面板、文档架构、iCloud）、全屏、Dock 菜单。

与 iOS 的关键差异：

- 不支持 Dynamic Type；用系统字体变体与标准控件一致。
- 控件推荐 28×28pt（最小 20×20pt）；指针点击比手指精确，但仍需间距。
- Sidebar 始终可见是常态；提供显示/隐藏按钮或 View 菜单命令。
- 不要在窗口底部放控件或关键信息。
- 用户可改系统强调色，Sidebar 图标要跟随。
- 支持拖放到 Finder、从非激活窗口直接拖出选中内容。
- 设置用 Settings 窗口（⌘,），不是 app 内的"设置"Tab。
- 有 Inspector、Toolbar 自定义、多窗口 / 多文档。

## 5. watchOS

- **快速、可瞥视、单屏**的交互：一两个手势完成目标操作。
- **导航层级最小化**；Digital Crown 用于纵向滚动或切换屏幕。
- **Complications** 把关键数据放到表盘，每次抬腕可见、点按直达；通常比打开 app 更常用。支持 tinted 模式、线条 ≥2pt。
- 通知与 Siri 交互是主要入口之一。
- 背景色用于传达信息，材质用于表达层级与场景感。
- 一排 ≤3 个图标按钮或 ≤2 个文字按钮；内容铺满到屏幕边缘。
- 长时间停留的界面避免全屏背景色。
- 支持文本放大至 140%。
- 全屏模态保留系统材质背景。

## 6. tvOS

- **焦点驱动**：遥控器移动焦点，焦点元素放大并带响应动画；**不要只靠颜色表示焦点**。
- 距离 3m 观看：默认字号 29pt、最小 23pt；控件推荐 66×66pt（最小 56×56pt）。
- 布局不随电视尺寸自动适配，需在多种尺寸验证；主要内容内缩上下 60pt、左右 80pt。
- 焦点放大时不得遮盖重要信息；网格间距一致；半露的离屏内容左右对称。
- 有限调色板呼应 logo，内容优先。
- 导航与系统体验（Top Shelf、控制中心）用 Liquid Glass；图片与按钮获得焦点时呈玻璃。
- 在多品牌 HD / 4K 电视与不同显示设置下测试。

## 7. visionOS

- **眼睛 + 手**：看着目标做间接手势（捏合）激活；也可直接触碰。系统悬停效果需要元素周围留空间——**按钮中心间距 ≥60pt**，按钮命中区 ≥60×60pt（次要控件最小 28×28pt）。
- **舒适度至上**：系统把内容相对头部放置，人不必移动；避免把内容锁在头部；保持在视野内；横向布局优先；减慢外围动画；镜头运动温和。
- **窗口、体积、沉浸空间**三种容器：Window 是 2D 平面（行为最像 iPad）；Volume 是有界 3D 区域（默认尺寸固定）；Immersive Space 环绕用户，需显式打开/关闭。
- **Ornament**：贴在窗口边缘、略靠前的 UI 平面，是 visionOS 的 Toolbar 与 Tab Bar 形态；控件放这里而不是挤进窗口或另开窗口。Tab Bar 位于窗口前导侧，注视稍久自动展开标签，≤6 项。Ornament 应是稳定、可瞥视的控件，不要在其中放争抢注意力的动效。
- 系统 glass 材质不可修改、无独立深色模式；窗口优先半透明；颜色省着用、用在粗体与大面积。
- 文本优先 2D、最大化对比、面向用户（billboarding）。
- 内容不越出窗口边界（系统控件在窗口上下方外侧）。
- 安全提示：不用于驾驶或危险环境，13 岁以上使用。

## 8. 跨平台移植检查

从 iPhone 移植到 iPad / Mac：

- 是否仍是一列窄内容居中？→ 用 `NavigationSplitView` 多栏、Inspector 利用宽度。
- 是否仍靠 Tab Bar 承载全部导航？→ iPad 用 `sidebarAdaptable`，Mac 用 Sidebar。
- 是否有菜单栏命令与键盘快捷键（Mac）？
- 是否依赖 Dynamic Type 做布局（Mac 不支持）？
- 是否把控件放在窗口底部（Mac）？
- Sheet 与全屏模态是否过多？→ 大屏用 Popover、Inspector、内联编辑替代。
- 设置是否在 app 内 Tab 里（Mac 应为 Settings 窗口）？
- 是否支持拖放、多窗口、指针悬停？

从 iPad / Mac 缩到 iPhone：

- 多栏是否折叠为 Stack？
- 控件是否移到可触达的中下部？
- 触控目标是否 ≥44pt？
- 键盘快捷键功能是否有触控入口？

到 watchOS：只保留最关键的一两个任务，其余交给 Complication 与通知。

到 visionOS：控件迁到 Ornament，检查 60pt 间距，去掉锁头部的内容，颜色减量。
