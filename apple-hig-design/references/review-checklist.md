# HIG 审查：清单与报告模板

当用户给出代码、截图或界面描述，想知道"哪里不像原生 / 有什么设计问题"时使用。审查不主动改代码，除非用户明确要求修复。

## 审查步骤

1. **确定平台与范围**：目标平台（可能多个）、审查的是哪几个界面 / 文件、是新建还是移植。把范围写进报告开头，让用户确认审的是对的东西。
2. **按清单逐项过**：下面的清单按 HIG 章节组织。对每一项记录：通过 / 不通过 / 无法从给定材料判断。"无法判断"也要写出来（例如只看代码看不出对比度），不要默认通过。
3. **每个发现给依据与修法**：说明违反了哪条 HIG 原则、为什么会让用户困惑、改成什么样。能给代码片段就给。
4. **分级**：
   - **阻塞**：会让部分用户无法使用或明显"不像这个平台"——触控目标过小、无 VoiceOver 标签、只靠颜色传达信息、自绘替代系统导航、Liquid Glass 用在内容层、macOS 上依赖 Dynamic Type。
   - **重要**：能用但体验明显不对——层级不清、模态滥用、Toolbar 堆满、大字号下截断、深色模式未测。
   - **建议**：锦上添花——同心圆角、触觉反馈、空状态文案、SF Symbols 替换自定义图标。
5. **列出需实机验证的项**：静态审查看不出的东西（对比度实测、Reduce Motion 下的动画、最大字号布局、不同窗口尺寸）。

## 清单

### A. 平台契合

- [ ] 布局利用了该平台的屏幕（Mac / iPad 不是拉宽的 iPhone 布局；iPhone 不是缩小的 iPad）
- [ ] 导航模型符合平台惯例（iPhone Tab Bar / Stack；iPad `sidebarAdaptable` 或 Split View；Mac Sidebar + 菜单栏 + 快捷键；watch 单屏 + Crown；visionOS Ornament）
- [ ] 控件位置符合平台（iPhone 中下部可达；Mac 不在窗口底部；visionOS 不越出窗口）
- [ ] 输入方式覆盖该平台（Mac / iPad 键盘与指针；tvOS 焦点；visionOS 注视 + 捏合间距 ≥60pt）
- [ ] 平台特有系统特性有合理集成（Widget、Spotlight、快捷指令、菜单栏、Complication）

### B. 层级 Hierarchy

- [ ] 第一眼看到的是内容而不是控件；主操作明显且一屏只有一个 prominent
- [ ] 功能层（Tab Bar / Toolbar / Sidebar）与内容层清晰分离；内容延伸到控件之下
- [ ] 次要信息与操作被适当收起（菜单、详情页、渐进披露），首屏不拥挤
- [ ] 视觉层级由字号、字重、颜色、间距一致地表达，而不是靠边框和阴影堆叠

### C. 系统组件与 Liquid Glass

- [ ] 凡有系统组件之处使用了系统组件（`TabView`、`NavigationSplitView`、`Toolbar`、`List`、`Form`、`Menu`、`sheet`、`Button` 样式）
- [ ] 自定义控件有明确理由，且自行处理了无障碍、状态、Reduce Motion
- [ ] Liquid Glass 只出现在功能层，没有用于列表、卡片、正文背景
- [ ] 没有玻璃叠玻璃；相邻玻璃元素在 `GlassEffectContainer` 内
- [ ] 着色克制：只有主操作 / 状态着色，且色在背景不在文字
- [ ] 嵌套圆角同心（`ConcentricRectangle`），没有随意的硬编码半径
- [ ] `clear` 玻璃只用于媒体之上并有压暗层

### D. 布局与自适应

- [ ] 尊重安全区与系统边距；没有全宽贴边按钮（iOS）
- [ ] 横竖屏 / 窗口缩放 / 外接显示器下布局可用；iPad 尽量晚切紧凑布局
- [ ] 元素对齐、分组清晰；不相关控件之间有足够间隔
- [ ] RTL 语言下布局镜像正确；文本长度变化不破坏布局
- [ ] 图片 @2x/@3x 且保持宽高比

### E. 排版

- [ ] 使用系统 text style 而非固定字号（macOS 除外，用系统字体变体）
- [ ] 字号不低于平台最小值；正文用默认字号；无 Ultralight / Thin / Light
- [ ] 字体家族 ≤2；层级由字重与字号表达并在放大后保持
- [ ] 最大无障碍字号下不截断关键文本、布局改为堆叠、图标随字放大

### F. 颜色与外观

- [ ] 使用语义色（`Color.primary`、`.secondary`、`systemBackground`…），未硬编码系统色值，未错用语义
- [ ] 自定义色提供浅 / 深 / 高对比变体；深色模式实际检查过
- [ ] 一种颜色一种含义；品牌色不用于不可交互的文字
- [ ] 信息不只靠颜色传达（有图标 / 文字 / 形状）
- [ ] tvOS 焦点不只靠颜色；visionOS 颜色克制

### G. 无障碍

- [ ] 按钮命中区 ≥ 平台推荐值（iOS / watchOS 44、macOS 28、visionOS 60、tvOS 66pt），次要控件不低于平台最小值（28 / 20 / 28 / 56pt），控件间留白足够
- [ ] 每个可交互元素有 accessibility label，仅图标按钮尤其检查；装饰性图片隐藏
- [ ] 文本对比 ≥4.5:1（大字 3:1），非文本 ≥3:1，深浅两种外观
- [ ] 所有手势有非手势替代；无自定义多指手势承载核心功能
- [ ] 响应 Reduce Motion / Reduce Transparency / Increase Contrast / Bold Text / Dim Flashing Lights
- [ ] 无定时自动消失的关键元素；音视频不自动播放或有可见控件
- [ ] Mac / iPad 可纯键盘操作；VoiceOver 焦点顺序合理
- [ ] 音频信息有文字替代与触觉配套

### H. 模式正确性

- [ ] Tab Bar 项数合理、不承载操作、不禁用
- [ ] Sidebar ≤2 层；返回行为标准
- [ ] 模态只用于需要注意或独立任务；有关闭方式；未保存修改有确认；无模态叠模态
- [ ] Alert 只用于关键信息，按钮文案说明后果
- [ ] Toolbar 按频率放操作，其余进菜单；主操作 prominent
- [ ] 搜索用 `searchable`，空结果有建议
- [ ] 空状态、加载、错误都有设计
- [ ] 权限在使用时请求并说明理由；Onboarding 可跳过、不重复
- [ ] Widget 可瞥视、深链正确、三种外观可用、非迷你 app

### I. 图标与品牌

- [ ] 界面图标优先 SF Symbols，语义未被误用
- [ ] App Icon 分层、四种外观、用 Icon Composer；无文字、无截图式图标
- [ ] 品牌表达在内容层（插画、图片、排版），功能层保持系统外观

## 报告模板

```markdown
# HIG 审查：<界面 / 模块名>

## 审查范围
- 平台：<iOS 26 / iPadOS / macOS Tahoe …>
- 材料：<文件列表 / 截图 / 描述>
- 未覆盖：<说明看不到的部分>

## 总体判断
<两三句：最像 / 最不像原生的地方，最需要先改的一件事>

## 阻塞
1. **<问题>** — <位置>
   - 现状：…
   - 依据：<HIG 章节 / 原则，为什么会让用户困惑>
   - 修法：<具体做法，必要时给代码>

## 重要
1. …

## 建议
1. …

## 通过项
<简要列出检查过且没有问题的类别，让"没发现问题"有分量>

## 需实机验证
- [ ] 最大 / 最小 Dynamic Type
- [ ] 深色模式与 Increase Contrast 下的对比度
- [ ] Reduce Motion / Reduce Transparency
- [ ] <平台特定：iPad 最小窗口 / Mac 多显示器 / visionOS 间距>
```

## 写发现时的语气

解释"为什么"而不是只说"不符合规范"。例如不写"违反 HIG：按钮太小"，而写"这个图标按钮约 24pt，手指点按的可靠命中需要 44pt，手指粗或运动障碍的用户会频繁误触相邻的删除按钮；用 `.frame(minWidth: 44, minHeight: 44)` 加 `.contentShape(Rectangle())` 扩大命中区，图标视觉尺寸可以不变"。用户看到的是可执行的修法与背后的原因，而不是一条规则编号。
